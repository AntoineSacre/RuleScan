How It Works
The engine assesses any public GitHub repository against CRA Annex I by collecting 29 inputs and evaluating them against a formal policy model. Of the 29 inputs, 25 are collected automatically from GitHub's public API — repository metadata, release history, advisory feeds, file presence, CI configuration. The remaining 4 require manual input from someone with knowledge of the project.

Under the hood, a Python script queries GitHub's public API of a targeted project using predefined heuristics (detailed below) to interpret the repository's characteristics (metadata, release history, security advisories, file presence, CI configuration). Once all inputs are gathered, the page sends them to the compliance engine via a web request. The engine checks each one against the CRA Annex I requirements and returns a rule-by-rule verdict in a few seconds.

01 Command-Line Quick Start ▾
1

Optional — set your GitHub token

Without a token, GitHub limits unauthenticated requests to 60/hour. A token with no special scopes raises this to 5,000/hour.

export GITHUB_TOKEN=ghp_...
2

Optional — start OPA for automated assessment

Start OPA from the repository root. Without it, the script collects data only and skips evaluation.

docker compose up -d   # run from the repository root
3

Run the use case

cd "Home Assistant Use Case"
./run.sh

Collects all 29 inputs, writes a timestamped data file to output/, and — if OPA is running — prints the compliance verdict.

04 Prerequisites ▾
  • bash, curl, jq, python3 — standard on macOS and most Linux distributions
  • Docker — only required for the automated assessment step (OPA)
  • A GitHub personal access token — optional but strongly recommended to avoid rate limiting
