How It Works
The engine assesses any public GitHub repository against CRA Annex I by collecting 29 operand values and evaluating them against a formal policy model. Of the 29 operands, 24 are collected automatically from GitHub's public API — repository metadata, release history, advisory feeds, file presence, CI configuration. The remaining 5 require manual input from someone with knowledge of the project. Under the hood, the engine calls collect.py with your repository parameters, then submits the collected data to OPA running the CRA Annex I policy. Results are returned as a rule-level compliance report in under a minute.

01 Command-Line Quick Start ▾
1

Optional — set your GitHub token

Without a token, GitHub limits unauthenticated requests to 60/hour. A token with no special scopes raises this to 5,000/hour.

export GITHUB_TOKEN=ghp_...
2

Optional — start OPA for automated assessment

Start OPA from the repository root. Without it, the script collects data only and skips evaluation.

docker compose up -d   # run from the repository root
3

Run the use case

cd "Home Assistant Use Case"
./run.sh

Collects all 29 operands, writes a timestamped data file to output/, and — if OPA is running — prints the compliance verdict.

04 Prerequisites ▾
  • bash, curl, jq, python3 — standard on macOS and most Linux distributions
  • Docker — only required for the automated assessment step (OPA)
  • A GitHub personal access token — optional but strongly recommended to avoid rate limiting
